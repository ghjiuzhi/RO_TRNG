# Journal of Cryptographic Engineering Venue Profile

Use this profile as general guidance for Journal of Cryptographic Engineering-style manuscripts. Do not include project-specific claims here.

## Good Fit

- Practical cryptographic engineering, secure hardware/software implementations, side-channel or fault evaluation, entropy sources, validation methodology, and security-oriented design.
- Papers where engineering evidence is tied to a clear security model or validation boundary.

## Writing Emphasis

- Define threat assumptions, security goals, and component boundaries.
- Separate empirical evidence from security claims.
- Explain standards-related tests carefully, including what they do and do not prove.
- Discuss health tests, conditioning, entropy accounting, and deployment implications when relevant.
- Keep implementation details connected to security consequences.

## Common Risks

- Presenting statistical tests as a complete security proof.
- Leaving entropy-source or module boundaries ambiguous.
- Overclaiming compliance or certification.
- Missing attacker model, validation assumptions, or operational health-test discussion.

## Revision Focus

- Clarify the security model and validation boundary.
- Strengthen entropy accounting and conditioning discussion.
- Add negative results and limitations where they affect security interpretation.
