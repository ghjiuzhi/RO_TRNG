For each complete 10 MiB TRNG capture, the preparation script currently writes:

- `bit-symbols-msb`: each raw byte is expanded into 8 one-byte binary symbols, MSB first.
- `bit-symbols-lsb`: same expansion, LSB first, used as bit-order sensitivity evidence.
- `byte-symbols`: raw byte symbols, retained for auxiliary analysis.

The current smoke runs use the first 1,000,000 prepared bit symbols. This is useful for screening and comparing placements, but it is not a full SP800-90B validation campaign.

## Caveats

- These are 1,000,000-symbol smoke runs, not complete formal SP800-90B certification results.
- The selected IID diagnostics reject the IID route, so the paper should use the non-IID values as conservative estimates.
- The current MinGW compatibility build uses local compatibility headers. It is suitable for smoke screening, but formal publication should record the exact source revision and build caveats.
- The build emitted a `uint128_t` fallback warning on this old MinGW path. The current non-IID smoke results completed, but a stronger paper artifact should ideally be reproduced with MSYS2/WSL or a modern compiler.
- Existing sequential `.bin` captures are not restart-test datasets. A formal SP800-90B claim still requires a restart collection protocol, e.g. independent restarts arranged as rows of one-byte symbols.
- Do not claim SP800-90B compliance yet. Claim only that the SP800-90B non-IID smoke estimator independently confirms the placement-dependent quality gap.
